# Requirements matrix

Each requirement, where it's written down, where it's built, and which test proves it. Paths are from the
repo root. "Smoke" and "edge cases" are `scripts/smoke.ts` and `scripts/edge-cases.ts`, run against a live app.

This is the finished design: a row holds in this repository once its feature is merged. Built so far: the server
base (route wrappers, errors, transactions, money as numbers, rate limits, jobs and the worker, emails), sign-in,
tenancy and permissions, creating a place, roles and team invitations (F13), account deletion and Download my data
(F17), platform admins, plans and their limits with Stripe and Whish (F15), and the Whish simulator. The smoke and
edge-case scripts come later.

## Gaps, stated plainly

- **Scheduled jobs and the worker**: the decision to answer now or queue, job states and errors are unit tested
  against a stand-in pg-boss. The worker itself (queued notices, schedules, retries) was checked by hand against a
  real Postgres, not in CI. Correctness doesn't depend on the schedule, because holds also expire per room on each
  request and feeds re-sync before confirming.
- **Real Airbnb and Booking.com links**: import is tested with Airbnb-style iCal files, not against a live
  listing. Export has not been read by a real platform yet.
- **Real Whish**: everything runs against the Whish simulator, built from Whish's API documentation. It hasn't
  met Whish's real sandbox yet, because Mabeet has no Whish keys. Card checkout is checked against Stripe's real
  test mode, but a completed card payment (and a card refund) needs the Stripe CLI forwarding webhooks.
- **Push notifications and installing the app** have no automated test beyond the endpoint check above, and
  have not yet been tried on a real phone.
- **Screens**: the newer screens (analytics, saved chats, notification pages, the calendar's drag and drop,
  whole-place booking, Contact host) are covered by unit and integration tests through their services and routes,
  and were clicked through in a browser, but the smoke and failure-case runs don't cover them yet.
- **Contact host emails** only reach real inboxes once a domain is verified on Resend.
- **Smoke and failure-case runs** need a running app, so CI doesn't run them. They are run by hand before a
  release.
