# Non-functional requirements

How well Mabeet must work, and how we make sure. What it does is in the
[functional requirements](functional-requirements.md).

| Area                          | The rule                                                                                                 | How we keep it                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **No double bookings**        | Two guests can never hold the same room night or the last seat                                           | The database itself refuses overlaps (an `EXCLUDE` constraint and a seat trigger). A test sends 20 requests for one room at once: 1 wins, 19 are told the dates are taken, 1 night range is stored. The whole place and its rooms block each other, also after the host switches how the place is booked: booking the whole place checks every room's nights, a room checks the whole place's, and bookings at one place take turns |
| **Business isolation**        | One business can never see or change another's data                                                      | The business comes from who you are, never from what you send. Foreign ids answer "not found". Tested over the website, API and MCP                                                                                                                                                                                                                                                                                                 |
| **Least privilege**           | People and AI only do what their role allows                                                             | Every rule is checked in the service layer, once, for screens, AI and MCP alike. Read-only keys lose every write permission                                                                                                                                                                                                                                                                                                         |
| **Privacy**                   | Guest phone and email only for roles allowed to see them                                                 | Contacts are masked otherwise. Calendar links never carry guest details. The AI never receives guests' contact details. A booking opens only for the signed-in guest who made it; anyone else gets "not found". Deleting an account signs the person out everywhere, frees their email and removes their name from their reviews. Download my data includes saved AI chats and the host profile                                     |
| **Nothing is deleted**        | Business data is kept, never removed                                                                     | Rows are marked `isDeleted` and every read skips them; creating a deleted category, role name or favourite again brings the old row back. Only short-lived technical rows are deleted: sign-in sessions and tokens, job progress and push devices. A test checks deleted accounts, categories, favourites and chats stay in the database but out of sight                                                                           |
| **Security**                  | Safe against the usual web attacks                                                                       | Input validated on every route, strict security headers, hashed keys, rate limits on public forms (bookings, Contact host) and AI, a guard against fetching private network addresses, uploads typed by their own bytes rather than their name                                                                                                                                                                                      |
| **Reliability**               | An email, push or AI outage never breaks a booking                                                       | Emails and push notifications are queued after the booking is saved and sent by the worker, retried up to 4 times, and survive a restart. AI errors show a friendly message                                                                                                                                                                                                                                                         |
| **Responsiveness under load** | A slow AI answer never holds up the website or other people                                              | Long or busy-time AI work goes to a queue (`ai`, 4 at once per worker) and the browser follows the job; the web process answers it within a request only when the estimate from the input is within `JOBS_SYNC_LIMIT_SECONDS` (5 s by default, so every AI answer today) and nothing is waiting. While queued, the reply is streamed: first words in about 2–3 s. More workers can be added without code changes                    |
| **AI responsiveness**         | Asking the AI never waits on bookkeeping                                                                 | Tool schemas are built once, a round's tool calls run in parallel, and audit logs and usage records are written after the answer is sent. Typing in the chat re-renders only the input box. A short first question is still answered at once, not queued                                                                                                                                                                            |
| **Money is never doubled**    | A payment confirms a booking once; payouts never exceed what is held; refunds never exceed what was paid | A payment is confirmed only after asking Whish or Stripe, in a transaction that marks it paid once (10 callbacks at once → 1 confirmation). Payout requests lock the business row (20 at once → 1). CHECK constraints cap refunds and require a payout destination                                                                                                                                                                  |
| **No commission**             | Hosts get every cent guests pay online                                                                   | No fee is computed anywhere: the balance is payments minus refunds minus payouts. Mabeet's income is plan payments only, recorded separately                                                                                                                                                                                                                                                                                        |
| **Card safety**               | Mabeet never handles card numbers                                                                        | Cards are entered on Stripe's own page. Payouts go to an IBAN or a Whish number; the form refuses anything else                                                                                                                                                                                                                                                                                                                     |
| **Cost control**              | AI spending can't run away                                                                               | A monthly budget. Admins are warned at 80%, and AI pauses at 100%                                                                                                                                                                                                                                                                                                                                                                   |
| **Speed on phones**           | Comfortable on weak mobile data                                                                          | Pages rendered on the server, optimised images, self-hosted fonts, loading skeletons                                                                                                                                                                                                                                                                                                                                                |
| **Accessibility**             | Usable with a keyboard or a screen reader                                                                | Real labels and headings, visible focus, and calmer motion for people who ask for it                                                                                                                                                                                                                                                                                                                                                |
| **Maintainability**           | Each rule is written once and easy to find                                                               | Routes, services and repositories kept apart, enforced by the linter. Strict TypeScript. No unused code (checked by knip). Value lists live once in `src/config/`; raw SQL only as tagged, parameterised templates                                                                                                                                                                                                                  |
| **Consistent design**         | Every screen looks and behaves the same, in light and dark mode                                          | Colours, radii and shadows are tokens in `globals.css`; components use token classes only. Shared UI (`Button`, `FormError`, dialogs) and hooks live in one place                                                                                                                                                                                                                                                                   |
| **Quality**                   | Every change is checked before it ships                                                                  | CI runs types, lint, formatting, unused code, unit and integration tests on every pull request                                                                                                                                                                                                                                                                                                                                      |

## Known limits

- A queued answer waits behind the jobs ahead of it. During a burst, the 5th question onward waits for one of the
  4 running AI jobs (per worker) to finish.
- Deleted rows stay in the database for good, and "Download my data" still includes the ones about the person.
- Airbnb and Booking.com refresh calendars on their own schedule, often every few hours. Clashes are shown to the
  host and never cancelled automatically.
